# 카브 스크립트 격리 보관소

2026-09-30 · 새 마키보 전투 구현 전 밑작업 · 상태: 검토 대기

이 폴더는 Unity의 `Assets` 및 `Packages` 밖에 있다. 하위의 `Assets/`는 원래 경로를 보존하는 보관용 디렉터리이며 Unity 임포트 대상이 아니다. 스크립트 49개와 각각의 `.cs.meta`를 원본 그대로 옮겼다. 새 런타임에서 이 코드를 참조하거나 컴파일 대상으로 포함하지 않는다.

- [manifest.json](manifest.json): 원래 경로, 격리 경로, 타입, GUID, SHA-256, 격리 이유, 남은 Assets 파일의 해시, 직접 GUID 참조 목록.
- [inventory.md](inventory.md): 파일별 격리 이유와 보존한 자체 코드 목록.
- [resource-references.md](resource-references.md): 격리한 GUID를 참조하는 리소스 56개/직접 참조 211건.
- [검토 기록](../../../docs/reviews/2026-09-30-carve-quarantine.md): 영향, 검증 결과와 다음 구현 범위.

## 보존과 의도한 중단

씬, 프리팹, ScriptableObject 데이터 에셋, 애니메이션, 이미지, 사운드, 입력 액션, 폴더 메타데이터는 삭제·이동·수정하지 않았다. 카브 코드에 연결된 리소스는 Missing Script/해석 불가능한 구형 데이터 참조를 포함한다. 카브의 전투·편성·저장·스테이지 진행 및 연결된 탐험 흐름은 현재 실행 대상으로 삼지 않는다. 데이터 에셋의 YAML 값과 GUID 연결은 보존되어 이후 새 데이터로 이행할 근거가 된다.

참조 목록은 텍스트 직렬화 파일의 직접 GUID 참조다. 프리팹을 통한 간접 영향, UnityEvent의 fileID 호출, 애니메이션의 문자열 메서드 호출까지 모두 센 숫자는 아니다. Missing Script를 일괄 제거하거나 기존 씬을 일괄 재저장하지 않는다.

독립적인 연출/기반 코드 12개와 자동 생성 입력 바인딩 `Assets/PlayerInput.cs`는 남겼다. 입력 바인딩은 보존된 `.inputactions`에서 재생성되는 코드이므로 폐기 대상으로 선정하지 않았다. 서드파티 플러그인과 예제 코드도 이번 격리에서 변경하지 않았다.

## 확인과 복구

저장소 루트에서 `& ./Tools/Verify-CarveQuarantine.ps1`을 실행하면 격리 파일·메타데이터 해시, 남긴 Assets 원본 해시, 격리 GUID의 재사용 여부와 남은 C#의 구형 타입 참조를 검사한다. 이 명령은 파일을 변경하지 않으며 Unity 컴파일을 대신하지 않는다. 이후 의도적으로 리소스를 변경하면 당시 보존 검사와 차이가 생기는 것이 정상이다. 원래 manifest를 새 결과로 덮어쓰지 말고 변경을 별도로 검토한다.

복구가 필요한 경우 Unity를 닫고 manifest의 `archivePath`와 `originalPath`를 대응시킨다. 각 `.cs`와 `.cs.meta`를 한 쌍으로 복구하되 목적지에 새 파일이 있으면 덮어쓰지 않는다. 의존 파일 일부만 복구하면 컴파일 오류가 생길 수 있으므로 의존 묶음을 확인한다. 저장소 전체 되돌리기로 사용자 씬 변경을 덮어쓰지 않는다. 보관본은 기본적으로 유지하며 새 마키보 코드는 별도 타입·네임스페이스·GUID로 만든다.
