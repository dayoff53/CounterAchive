# 전환 계획과 진행 상태

기준일: 2026-10-01. 아래 구현 순서는 Codex의 제안이며, 게임 규칙의 추가 확정이 아니다.

## 현재 위치

- 프로젝트 방향: CounterAchive → **마세이 키보토스** 전환.
- 완료한 작업: 개발 문맥 구성, 카브 코드 격리, 새 턴 기반, Stage_Battle의 InGame 리소스 연결. 기존 프리팹/스프라이트는 보존.
- 현재 제출 상태: **Stage_Battle 리소스 연결 검토 대기**. [작업 기록](reviews/2026-10-01-stage-battle-resources.md). 별도 프로젝트 복사본에서 Unity 컴파일 및 EditMode 12개/PlayMode 2개 테스트 통과. 검토 완료를 의미하지 않음.
- 새 전투 구현: 2세력 PvE에서 턴 종료만 예약하는 범위. 스킬·이동·상태·교체 등은 미구현. Stage_Battle은 새 실행 기준이며 나머지 카브 씬의 기존 진행 흐름은 연결하지 않았다. [새 리소스 연결 기록](reviews/2026-10-01-stage-battle-resources.md).
- 다음 권장 작업: 턴 화면 검토 후 일반 스킬/대상/자원 예약 실행을 연결하고 M1/M2의 나머지 범위를 확장.

AI의 난이도·행동 정책, 온라인 방식, 콘텐츠 분량은 별도 범위 결정이 필요하다. 간단한 조작 화면/로그는 M1부터 붙여 단계마다 확인 가능하게 한다. 단계별로 필요한 승패·타깃 기초를 먼저 구현할 수 있으며, 표가 모든 세부 작업의 엄격한 직렬 순서를 강제하지 않는다.

## 다음 구현에서 확인할 사항

- 카브 AP 누적 로직은 Assets 외부로 격리했다. 새 Speed 전투는 별도 네임스페이스와 어셈블리로 작성하고 구형 코드에 의존하지 않는다.
- 새 전투용 씬에서 시작한다. 카브 씬·프리팹의 Missing Script를 일괄 제거하거나 구형 코드를 복원해 숨기지 않는다. 리소스 재사용 시 필요한 시각 요소를 가져와 새 코드로 연결한다.
- 씬 연결을 바꾸기 전에 기존 사용자 작업과 `Stage_DD_Battle_2.0`의 의도를 해당 파일에서 확인한다.
- [미정 항목](DECISIONS.md) 중 교체 후 예약 정리, 대상 승계, 헤일로 이상 처리 순서는 관련 기능 구현 시 해소한다.
- 첫 테스트 범위 후보: 첫 턴 COST, 필드 수/배치 제한, Speed 순서와 현재 행동권 유지, 실패 후 다음 예약, 공격·필수 후속 효과 뒤 종료.

## 상태 갱신 기준

- **구현 전**: 해당 작업 단위에 착수하기 전. 기존 코드가 전혀 없다는 뜻은 아니다.
- **진행 중**: 구현 또는 필수 검증을 수행 중.
- **검토 대기**: 결과·검증 수준·재현 절차를 dayoff53에게 제출한 상태.
- **검토 완료**: dayoff53의 확인/피드백을 받은 뒤 기록한 상태.

테스트 통과 여부는 상태 이름에 숨기지 말고 검토 기록에 별도로 남긴다. 후속 작업에서는 관련 행과 현재 위치를 갱신하고, 오래된 제안을 확정 요구사항처럼 취급하지 않는다.
