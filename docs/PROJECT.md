# 프로젝트 기준

작성일: 2026-09-29 · 프로젝트 책임자/검토자: **dayoff53**

## 프로젝트의 목표

게임명은 **마세이 키보토스**, 약칭은 **마키보**다. 기존 `CounterAchive`를 [2026-09-23 전투 규칙](reference/battle-rules-2026-09-23.txt)에 맞게 수정하고, 플레이 가능한 게임으로 완성한다.

기존 게임 **카운터 아카이브**는 **카브**라고 부른다. 2026-09-30 dayoff53은 기능이 겹치거나 불필요한 카브 스크립트 및 강한 의존 코드를 `Assets` 밖으로 격리하고 마키보 코드를 새로 작성하기로 결정했다. 리소스는 보존하며, 실제로 폐기해야 하는 예외가 생기면 이유를 보고한다. [격리 결과](reviews/2026-09-30-carve-quarantine.md).

제목은 원문에서 설명한 ‘키보토스에서의 여정들’이라는 의미를 따른다. 저장소/폴더 이름 `CounterAchive`는 기존 구현의 식별자로 남아 있으며, 사용자에게 설명하는 새 프로젝트 이름과 구분한다.

## 역할과 작업 방식

| 담당 | 책임 |
| --- | --- |
| Codex | 기존 구현 조사, 작업 분할, 설계 선택, 코드/에셋 연결, 적절한 검증, 문서 갱신, 검토 가능한 결과 제출 |
| dayoff53 | 게임 방향 및 미정 게임 규칙 결정, 기능 결과와 플레이 경험 검토, 수정 의견 제시 |

사용자가 요청한 기능의 구현 방법은 Codex가 주도한다. 일상적인 코드 구조나 가역적인 수정마다 사전 승인을 받는 절차를 만들지 않는다. 규칙의 의미나 플레이 결과가 달라지는 미정 사항은 가능한 선택과 영향을 구체화하여 확인한다. 해당 결정과 무관한 작업은 계속할 수 있다.

검토 대기는 매 코드 수정의 사전 허가를 뜻하지 않는다. 구현·검증한 결과를 dayoff53이 확인할 수 있게 제출한 상태를 뜻한다.

## 기준의 우선순위

1. dayoff53이 현재 작업에서 명시적으로 확정한 최신 게임 규칙/프로젝트 결정.
2. [결정 기록](DECISIONS.md)에 날짜와 근거를 적은 확정 변경.
3. 제공받은 [전투 규칙 원문](reference/battle-rules-2026-09-23.txt).
4. [규칙 요약](BATTLE_RULES.md)과 개발 계획.

위 순서는 게임 명세 내부의 우선순위다. 문서 요약, Codex의 제안, 구형 코드가 확정 규칙을 변경하지 않는다. 충돌의 확정 시점을 알 수 없다면 추정으로 해소하지 말고 기록한다.

## 이번 환경 구성의 범위

- 저장소 루트에 Codex가 참조하는 `AGENTS.md`를 둔다.
- 첨부 원문을 저장소 안에 보존하여 채팅 첨부 경로에 의존하지 않는다.
- 확정 규칙, 현재 구현, 미정 결정, 앞으로의 구현 작업을 구분한다.
- Codex 구현 → 검증 결과 제출 → dayoff53 검토가 이어지는 절차를 정한다.

게임 로직 교체, 일괄 파일명/네임스페이스 변경, Unity 제품명 변경, 에디터 업그레이드, 출시 빌드 생성은 후속 작업이다. 이번 구성의 완료가 게임 완성을 뜻하지 않는다.

## 게임 완성의 판단

최종 목표는 규칙에 맞는 전투와 게임 진행을 실제로 플레이할 수 있는 상태다. 다음 항목은 개발을 위한 완료 판단 틀이며, 제공되지 않은 콘텐츠 규모나 플랫폼을 임의로 확정하지 않는다.

- 확정된 전투 규칙과 예외가 데이터·로직·UI에 반영되고 재현 가능한 검증이 있다.
- 편성, 전투 시작, 예약, 실행, 승패, 다음 진행 흐름을 실제 Unity에서 확인한다.
- 스킬/유닛/아이템/스테이지 데이터가 필요한 범위에서 연결되고 누락 참조가 없다.
- 관련 기능의 미정 규칙이 해소되거나 명시적으로 후순위로 분리되어 있다.
- 목표 플랫폼·콘텐츠 범위·배포 형태를 정하고 해당 빌드를 검증한다.
- dayoff53의 검토 의견과 해결 결과가 기록된다.

PvE/PvP 규칙은 원문에 모두 있다. 이것만으로 온라인 멀티플레이, 서버, 매칭, 캠페인 분량을 확정하지 않는다. 범위가 필요한 시점에 [결정 기록](DECISIONS.md)에서 다룬다.

## 문서 유지

원문은 제공 시점의 스냅샷으로 보존한다. 후속 규칙은 결정 기록에 추가하고 요약·테스트·데이터에 함께 반영한다. 기능 작업 후에는 관련 구현 현황과 진행 상태만 갱신한다. 문서는 작업자가 실제로 수정하여 유지하는 것이며, 모든 대화가 자동 저장되는 것은 아니다.
