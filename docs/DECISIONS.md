# 확정 결정과 미정 사항

기준일: 2026-10-04. 원문 근거의 행 번호는 [보존본](reference/battle-rules-2026-09-23.txt) 기준이다.

`확정`은 dayoff53의 명시적 결정 또는 제공된 규칙이다. `미정`은 원문이 결정을 남긴 사항, `검토 후보`는 구현을 위해 Codex가 발견한 명세 공백이다. 검토 후보가 새로운 게임 규칙을 뜻하지 않는다.

### D-007 · 헤일로 이상 처리 순서 확정

- 날짜/상태/결정자: **2026-10-02 / 확정 / dayoff53**. 사용자가 구체적인 제안 순서에 “제안한 순서로 확정하고 구현”이라고 답변했다.
- 관련: 원문 11절, **Q-001/Q-002/C-008 해결**. 원문 보존본은 수정하지 않는다.
- 순서: **퇴각·행동 금지 등 사용자 제한 검사 → BP 0 대체 결정 → 범위 피해 → 최대 HP 55% 소모 및 자체 BP 완충 → 모든 후속 처리 후 승패 판정**.
- 대체가 결정되면 원래 스킬의 대상 소멸/사거리 이탈 검사는 생략한다. 원래 BP가 실행 전에 회복되었다면 원래 스킬을 실행하고 원래 대상/사거리를 재검사한다.
- 최대 HP의 55% 소모량은 **올림**한다. 범위 공격의 명중 여부와 관계없이 HP 소모와 헤일로 이상 자체 BP 완충을 처리한다. 원래 스킬 BP는 회복하지 않는다.
- 이유: 대체와 무효 판정이 겹치는 경우를 일관되게 처리하고, 마지막 적 퇴각만으로 필수 자기 HP 소모를 생략하지 않기 위함.
- 영향: `TurnBattle.Skills.cs`, `TurnBattle.cs`, `BattleRoster.cs`, `MainSkill.cs`, 스킬 UI, `HaloAnomalyTests.cs`, 실제 씬 PlayMode. [구현·검토 기록](reviews/2026-10-02-main-skills.md).

### D-008 · 이동 예약의 예시 배치와 실제 실행 분리

- 날짜/상태/결정자: **2026-10-02 / 확정 / dayoff53**. 서브 이동 구현 요청에서 명시했다.
- 4단계에서는 이동 예약 결과를 유닛 이미지로 미리 보여 준다. 5단계 시작 시 예시 이미지를 제거하고 실제 위치에서 예약 행동을 순서대로 실행한다.
- 이는 연출 요구이며 이동·서브 소비·이동 불가의 원문 8·9·14절 규칙을 변경하지 않는다.
- 구현 선택: 별도 좌표 복사본/렌더러로 아군 이동만 예측한다. 적의 비공개 예약·스킬 피해는 반영하지 않으므로 실제 실행 결과와 다를 수 있음을 화면에 표시한다.
- 예제의 이동 거리 **3칸**은 기능 확인용 임시 데이터다. 유닛별 최종 이동 거리를 확정한 결정이 아니다.
- 영향: `TurnBattle.Movement.cs`, `MovementPanel.cs`, 두 전투 화면/컨트롤러, 이동 규칙/씬 테스트. [구현·검토 기록](reviews/2026-10-02-movement.md).

### D-009 · 이동 금지 중 재시도의 디버프 재부여 제외

- 날짜/상태/결정자: **2026-10-04 / 확정 / dayoff53**. “이동 불가 상태에서 이동 시도 시 이동 불가 상태에 빠지지 않도록” 요청했다.
- 실행 시 이미 이동 불가 횟수가 남아 있거나 외부 이동 금지 상태라서 실행하지 못하면, 이동 불가 2회를 새로 부여하거나 남은 횟수를 갱신하지 않는다. 기존 상태도 즉시 해제하지 않는다.
- 원문 14절의 실패 시 2회 부여 규칙에 대한 예외다. 원문 보존본은 수정하지 않는다. 이동 금지가 없는 상태의 경로 차단·거리 등 다른 실패와 정상 이동에는 기존 2회 부여를 유지한다.
- 변경 요청이 없는 서브 1회 소비 및 자기 턴 종료 시 잔여 1회 감소는 유지한다. 예: 잔여 1회 → 재시도 후 1회 → 자기 종료 후 0회.
- 미리보기와 실행에 동일하게 반영하고 진행 로그에 재부여 없음을 표시한다. [변경·검증 기록](reviews/2026-10-04-movement-lock-retry.md).

문서 분리/로직과 연출 분리 권장은 Codex의 개발 구성 선택이며 별도 게임 규칙이 아니다.

## 이후 결정을 남기는 방법

새 결정에는 `ID / 날짜 / 상태 / 결정자 / 관련 원문 절 또는 Q·C ID / 확정 내용 / 이유 / 영향 파일·테스트`를 적는다. dayoff53의 결정이 오면 관련 미정의 해결 근거를 연결하고, 원문 스냅샷은 보존하면서 규칙 요약·구현·검증 사례를 갱신한다. 검토 후보나 임시 구현을 이유 없이 `확정`으로 바꾸지 않는다.
