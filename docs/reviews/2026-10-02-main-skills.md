# 메인 행동: 일반 공격 스킬 1차 구현

날짜: 2026-10-02 / 상태: 검토 대기 / 검토자: dayoff53

## 목적과 범위

`Stage_Battle`의 기존 InGame 리소스를 그대로 사용하면서, 매 턴 아군별 스킬과 대상을 예약하고 실제 HP/BP/COST 변화를 확인한다. `TurnSandbox`에도 같은 선택 창과 Core를 연결한다.

이번 구현은 **유닛 지정·적 단일 대상·단발 태크/신비 공격과 BP 0 대체인 헤일로 이상**이다. 변화 스킬, 일반 광역/다단 공격, 상태 효과의 지속 시간, 이동/교체, EX, 아이템, 공격 애니메이션, 적 스킬 선택 AI는 포함하지 않는다. 적은 기존처럼 종료를 예약하는 검증용 상대다.

규칙 근거는 [원문](../reference/battle-rules-2026-09-23.txt)의 2절(퇴각과 후속 효과), 8~10절(예약·메인·턴 종료), 11절(BP·Type·Trait·피해), 13절(유닛 지정·사거리)이다. 기존 카브 스크립트를 다시 연결하지 않았다. 스크립트 외 리소스의 수정·폐기는 없다.

## 직접 확인할 순서

1. Unity `6000.5.10f1`에서 `Assets/Scenes/Stage/Battle/BattleType/Stage_Battle.unity`를 열고 Play한다.
2. 오른쪽 위 **메인 스킬**을 누른다. **아군 A → 기본 사격 → 9번 적군 X → 예약 적용** 순서로 선택한다.
3. 같은 창에서 **아군 B → 기본 사격 → 8번 적군 Y → 예약 적용** 후 **닫기**를 누른다.
4. **예약 확정**을 누르면 실행 단계로 전환한다. 다음 **다음 단계 / 행동**은 A의 차례 시작, 그다음은 스킬 실행이다.
5. X의 HP가 **100 → 70**, A의 메인 횟수가 0이 된다. A의 차례는 아직 끝나지 않았으며 다음 진행에서 마지막 턴 종료를 실행한다.
6. **턴 넘기기**로 남은 차례를 진행하면 B도 예약한 공격을 실행하고 다음 턴으로 간다. X/Y의 HP는 유지된다.
7. 메인 스킬 창에서 기본 사격 BP가 **5 → 4**인지 확인한다. **처음부터**를 누르면 HP/BP/COST/턴 번호/예약이 모두 초기화된다.
8. **신비탄**을 예약하면 공유 COST의 예약 확보가 1 증가하지만 실제 COST는 즉시 줄지 않는다. **스킬 취소 · 종료만 예약**으로 확보분을 해제할 수 있다.

아군 슬롯을 직접 클릭하는 기존 조작은 해당 유닛의 **예약 전체 취소/종료 예약**이다. 스킬 예약이 있는 상태에서 취소하면 스킬도 함께 지워진다. 창을 단순히 닫는 것은 이미 적용한 예약을 취소하지 않는다. 선택만 하고 `예약 적용`을 누르지 않은 내용은 실행하지 않는다.

### 기능 확인용 데이터

| 스킬 | 분류/속성 | 위력/명중 | 최대 BP | COST | 사거리 |
| --- | --- | --- | --- | --- | --- |
| 기본 사격 | 태크/무 | 20 / 100% | 5 | 0 | 0~8 |
| 신비탄 | 신비/무 | 32 / 85% | 3 | 1 | 0~8 |

모든 임시 유닛은 HP 100, 공격/방어 10, 무속성이다. 기본 사격 피해는 `ceil(10/10 × 20 × 1 × 1.5) = 30`, 신비탄 적중 피해는 48이다. 이름과 수치는 검증용 임시 콘텐츠이며 실제 캐릭터 밸런스 또는 Q-006의 확정 답이 아니다.

## 작동 순서와 자원

1. 4단계에서 사용자·스킬·대상 ID를 저장한다. 한 유닛은 메인 스킬 하나와 마지막 종료 행동을 가진다. 스킬 예약 수정은 기존 예약을 대체한다.
2. COST는 예약에 확보하되 아직 소비하지 않는다. 현재 공유 COST를 넘는 추가/수정 예약은 거부하며, 수정 실패 시 원래 예약을 유지한다. 예약 취소는 확보분을 해제한다. 이는 현재 지원 범위의 회계 처리이며 미래 자원 변화 효과의 모든 우선순위를 확정한 것은 아니다.
3. 확정 순간 원래 스킬 BP가 0인지 기록한다. 실행 단계에서는 예약을 편집하지 않는다. 턴 넘기기는 스킬을 덮어쓰지 않고 누락된 종료 예약만 보완한다.
4. Speed 순서로 사용자 차례를 시작한다. 다음 진행에서 스킬을 한 번 시도한다. 현재 대상 위치·생존·적 여부·사거리·자원을 다시 검사한다. 유닛 지정은 원래 ID를 추적하며 다른 적으로 자동 변경하지 않는다.
5. 일반 스킬 시도는 메인 1회와 BP 1을 소비한다. 대상 무효/사거리 이탈 등 취소 시 COST는 소비하지 않는다. 명중 실패는 BP와 COST를 소비하며 HP는 그대로다. 확정 때 BP가 있었지만 실행 전 0이 되면 음수 차감과 대체 없이 취소한다.
6. 적중 시 분류별 공격/방어, 11속성표, 복합 상성 제한 0.5~2, 자속 1.5를 적용한 뒤 최종 한 번만 올림한다. 계산용 방어력만 최소 1이며 원본 방어력을 바꾸지 않는다. 정확히 0인 피해는 0이다.
7. HP 0인 대상은 퇴각하고 남은 예약에서 제외된다. 이번 단발 공격에는 추가 후속 효과가 없으므로 퇴각 반영 후 기존 승패 검사를 호출한다. 향후 반동/광역은 이 경로를 그대로 반복 호출하면 안 되며 필수 후속 효과까지 묶어야 한다.
8. 전투가 계속되면 다음 진행에서 사용자 턴 종료를 처리한다. 새 턴에 HP/BP는 유지하고 메인 횟수와 예약은 새로 준비한다.

## 확정된 BP 0 대체: 헤일로 이상

dayoff53이 제안 순서를 명시적으로 승인하여 [D-007](../DECISIONS.md)로 기록했다. Q-001/Q-002/C-008은 해결되었고 임시 실행 중단 경계는 제거했다.

1. 퇴각·메인 스킬 사용 금지 등 사용자 제한을 먼저 검사한다. 제한이 있으면 대체로 우회하지 않는다.
2. 확정 시와 실행 시 모두 원래 BP가 0이면 **헤일로 이상**으로 대체한다. 원래 대상의 소멸/사거리 이탈을 이유로 취소하지 않는다. 확정 때 0이었다가 실행 전 회복되었으면 원래 스킬을 실행한다.
3. 자신의 현재 슬롯과 양옆 1칸을 대상으로 한다. 1~9 경계에서 잘리며 자신·아군·적군을 모두 포함한다. 무속성 신비, 위력 50, 대상별 명중 80%다. 대상별 명중/피해를 모두 계산한 뒤 HP를 반영하고 퇴각을 처리한다.
4. 모든 대상이 빗나가거나 시전자가 범위 피해로 이미 퇴각했어도 필수 후속 처리를 끝낸다. `ceil(최대 HP × 0.55)`를 소모하며 생존 HP 1을 보장하지 않는다. 자체 BP만 40까지 완충한다.
5. 마지막으로 승패를 판정한다. 적 전멸 후 자기 HP 소모로 아군도 전멸하면 PvE에서는 패배다. 시전자 생존 시에는 메인만 소모되고 다음 진행에서 마지막 턴 종료를 실행한다.

원래 스킬의 BP는 0으로 유지하고 원래 COST는 소비하지 않는다. 선택 창은 BP 0에서 자신/아군 피해와 HP 소모를 안내한다. `SetMainSkillBlocked`는 외부 효과가 금지 여부를 전달하는 입구이며, 특정 상태 이상이나 지속 시간을 새로 확정한 기능은 아니다.

직접 확인하려면 A만 신비탄을 3번 사용하여 BP 0으로 만든다. 다른 아군은 종료만 예약하고, 적이 하나 이상 남은 다음 턴에 A의 원래 신비탄을 다시 예약한다. 헤일로 이상을 직접 선택하는 버튼은 없다. 자동 대체 후 A/B의 피해, 자기 HP 소모, 자체 BP 40과 원래 BP 0을 확인한다. 테스트에서는 실행 단계의 BP 변경 API로 고갈 상태를 재현하므로 명중 난수에 관계없이 같은 경계를 검사한다.

## 파일별 역할

- `Core/MainSkill.cs`: 일반 스킬 정의, 분류/11속성, 예약 데이터, 피해 계산. 속성표는 원문 방향 그대로이며 역방향을 자동 생성하지 않는다.
- `Core/BattleRoster.cs`: 유닛별 소유 스킬/속성, 현재 HP와 스킬별 BP. 같은 정의를 공유해도 전투 중 BP는 유닛마다 독립적이다.
- `Core/TurnBattle.Skills.cs`: 메인 예약·COST 확보·실행 재검사·명중·피해·BP 변경, 행동 금지 입력, 헤일로 이상과 필수 후속 처리.
- `Core/TurnBattle.cs`: 기존 5단계에 스킬 실행 한 단계를 연결하고 종료 예약을 별도로 유지한다. 퇴각/새 턴/전투 종료에서 관련 예약을 정리한다.
- `Unity/MainSkillPanel.cs`: 사용자·스킬·9칸 대상 선택, 예약 적용/취소, 자원 안내. 화면 계산은 Core 상태를 읽으며 피해 규칙을 복제하지 않는다.
- `Unity/TurnSandboxController.cs`: 두 씬의 공용 입력과 갱신, 임시 스킬 데이터, 안전한 자동 진행.
- `Unity/StageBattleView.cs`, `TurnSandboxView.cs`: HP·스킬 예약·실행 결과 표시.
- `Tests/EditMode/MainSkillTests.cs`, `HaloAnomalyTests.cs`, `Tests/PlayMode/StageBattleTests.cs`, `TurnSandboxTests.cs`: 규칙 경계와 실제 UI 조작/턴 연결 검증.

새 타입·함수·프로퍼티·필드와 주요 지역 변수에는 한국어 역할 주석을 작성했다. 기존 `docs/code-guide/`와 Notion 해설은 `f69ceba` 기준의 이전 스냅샷이므로 이번 추가 코드를 설명하는 최신본으로 취급하지 않는다.

## 검증

열려 있는 원본 에디터 대신 `Logs/StageValidation` 사본에서 Unity `6000.5.10f1`로 실행했다. 원본 직접 조작·플레이어 빌드와 구분한다.

- **컴파일:** 변경 코드 CS 오류 없이 성공. 최종 PlayMode 실행에서 UI 보정 후의 코드도 재컴파일했다.
- **EditMode 45/45 통과:** 기존 12개 + 일반 공격 24개 + 헤일로 이상 9개. 예약 자원 보존, 과다 확보/수정 실패, 명중 실패, 사거리 경계, 대상 퇴각, 확정 뒤 BP 소진/회복, HP/BP 턴 간 유지, 퇴각/승패, 11×11 상성 전체, 복합 배율 상하한, 최종 올림, 입력 검증을 포함한다. 헤일로 이상은 양 끝 범위, 대상별 명중 79/80 경계, 전체 빗나감 시 후속 효과, HP 101의 소모량 56, 사라진 원래 대상, 행동 금지/시전자 퇴각, 후속 HP 소모에 따른 승리/동시 전멸 패배를 검사했다. `Logs/skills-halo-editmode-reviewed.xml`.
- **PlayMode 4/4 통과:** Stage_Battle 스킬 선택/취소/재예약/실행/초기화, BP 0 대체와 다음 턴, 기존 Stage_Battle과 TurnSandbox의 턴/스킬 조작을 포함한다. 실제 Canvas raycast와 클릭 이벤트를 사용했다. `Logs/skills-halo-playmode.xml`.
- **화면:** [선택 창](evidence/2026-10-02-skill-planning.png), [사격 후 X의 HP 70](evidence/2026-10-02-skill-hit.png). 기존 캐릭터/배경/슬롯, UI 겹침, HP/Speed 줄바꿈을 렌더링으로 확인했다.
- **대체 화면:** [BP 0 안내](evidence/2026-10-02-halo-planning.png), [헤일로 이상 실행 후](evidence/2026-10-02-halo-executed.png). 실제 테스트에서는 인접 B의 HP 25, A의 HP 소모/퇴각과 자체 BP 40을 확인했다.
- **사본 일치:** 마키보 코드/메타/씬, Stage_Battle, DDBattleInGame 프리팹, 패키지 선언/잠금, 프로젝트 버전의 SHA-256이 58개 모두 일치했다. 별도로 비교한 `ProjectSettings.asset` 한 개는 사본의 Unity 설정 이행(serializedVersion 28→29, 플랫폼 기본값 등) 차이가 있다. 원본 설정을 사본으로 덮어쓰지 않았다. [검증 JSON](evidence/2026-10-02-skill-tests.json), [설정 차이](evidence/2026-10-02-validation-settings-diff.json).
