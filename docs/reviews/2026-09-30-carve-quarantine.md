# 카브 전투 및 의존 스크립트 격리

2026-09-30 · 상태: **검토 대기** · 검토자: dayoff53

## 목적과 확정 범위

dayoff53의 요청에 따라 카운터 아카이브(카브)의 전투 코드를 Assets 밖으로 격리하여 마세이 키보토스(마키보)의 새 전투와 혼용되지 않게 한다. 관련 결정은 D-004~D-006이다. 전투 규칙 자체를 변경하거나 미정 규칙을 확정하지 않는다. 이번 작업은 M0-Q 밑작업이며 M1~M6 구현 완료를 뜻하지 않는다.

현재 브랜치 `Remake/SetCodex`에서 작업했다. 기존 사용자 변경인 DDBattleInGame.prefab, SkillSlot.prefab, LoadingScene.unity, 미추적 Stage_DD_Battle_2.0 씬과 메타데이터를 보존했다. README·AGENTS·프로젝트 문서는 기존 내용을 바탕으로 이번 결정과 상태만 갱신했다.

## 변경 결과

- 자체 스크립트 49개와 `.cs.meta` 49개를 [Legacy/Carve/2026-09-30](../../Legacy/Carve/2026-09-30/README.md)으로 원래 하위 경로를 유지하여 이동했다.
- AP 누적, 시간 기반 COST, 턴·스킬·슬롯·배치·승리 UI, 기존 유닛/스킬/스테이지 데이터 구조를 실행 대상에서 제외했다.
- `UnitStatus/UnitData/SkillData → DataManager → 편성/저장/스테이지 선택` 및 `DataManager → ExploreStageMaster → 탐험 입력/상호작용` 의존 관계에 따라 관련 코드도 격리했다. SceneKeyData에 구형 전투 상태 enum과 UnitStatus가 묶여 있어 기존 씬 전환 코드도 함께 격리했다.
- 내용이 없거나 실제 기능이 없는 클래스, 구형 전투 전용 사전/템플릿 코드도 격리했다. 각 이유는 [파일별 목록](../../Legacy/Carve/2026-09-30/inventory.md)에 있다.
- 전투 규칙에 의존하지 않는 카메라·페이드·풀링·코루틴·시각 효과 등 12개 자체 스크립트를 유지했다. 자동 생성 PlayerInput.cs와 서드파티 코드는 보존했다.
- 구형 클래스의 호환 껍데기나 새 전투인 것처럼 보이는 임시 대체 로직은 추가하지 않았다.
- **스크립트 외 리소스 폐기: 0개.** 리소스 및 남은 코드/메타데이터 총 3,978개 파일을 작업 전 SHA-256과 비교했다.

## 끊긴 연결과 영향

보존된 직렬화 리소스 56개에 격리한 스크립트 GUID 직접 참조 211건이 있다. [리소스별 참조 목록](../../Legacy/Carve/2026-09-30/resource-references.md)은 원래 파일 경로와 행을 기록한다. DDBattleInGame.prefab에는 29건, STSBattleInGame.prefab에는 25건이 있다. 프리팹을 사용하는 씬으로 전파되는 간접 영향은 이 숫자보다 넓다.

기존 씬/프리팹은 Missing Script를 포함하며, 구형 ScriptableObject는 해당 스크립트로 해석되지 않는다. 이는 구형 코드의 격리 결과이고 파일 내용 손실을 뜻하지 않는다. 카브의 기존 전투·메뉴 진행·저장 및 의존 탐험 흐름은 플레이 불가 상태다. 파일ID 기반 UnityEvent나 애니메이션 이벤트를 새 코드로 연결한 것도 아니다.

원본 리소스를 유지하기 위해 Missing Script 컴포넌트 제거, 데이터 에셋 변환, 빌드 씬 변경, 일괄 재저장을 수행하지 않았다. 실제 세이브 파일과 Unity 제품명·회사명도 변경하지 않았다.

## 검증

- `Tools/Verify-CarveQuarantine.ps1`: 격리한 49쌍의 파일 해시 일치, 남긴 3,978개 Assets 파일 해시 일치, Assets 내 격리 GUID 재사용 없음, 남은 전체 C# 코드에서 격리 타입 참조 없음. 정적 문자열 검사이며 컴파일 증거와 구분한다.
- Unity 6000.5.10f1 배치 스크립트 컴파일: **통과**. 실제 `Assembly-CSharp.dll` Csc 실행 및 도메인 재로드를 확인했고 C# 컴파일 오류 없이 종료 코드 0을 반환했다. 컴파일 후에도 위 보존 검사를 다시 통과했다. [검증 증거](2026-09-30-carve-quarantine-compilation.md).
- 에디터 초기화: **문제 있음**. 보존된 Sirenix/Odin의 `GUITimeHelper.Init`, `ImguiElementUtils.Init`에서 Unity UIElements의 `s_BeginContainerCallback` 필드에 대한 `MissingFieldException` 2건이 발생했다. 플러그인과 현재 Unity 사이의 호환성 문제로 추정되며 이번 격리 전 재현 여부는 확인하지 않았다. 플러그인은 수정하지 않았고 에디터 전체 정상 동작으로 보고하지 않는다.
- 유지한 코드에서 C# 경고 5종: FadeManager.Awake 숨김, Singleton의 폐기 예정 탐색 API, PlayerCameraController의 미사용 필드 3개. 구형 전투 참조 오류는 없음.
- 문서의 로컬 링크 222개와 문서/검증 도구의 공백·문자 검사를 통과했다. 규칙 원문 SHA-256도 기존 보존값과 일치한다.
- 전체 `git diff --check`는 기존 사용자 변경인 SkillSlot.prefab/LoadingScene.unity의 공백 7곳을 보고한다. 이 파일들의 SHA-256은 작업 전과 같으며 공백 정리는 하지 않았다. 이번에 작성한 문서/도구의 별도 공백 검사는 통과했다.
- Play Mode/플레이어 빌드/새 전투 규칙 테스트: 실행하지 않음. 이번 작업은 기존 실행 경로를 폐기하는 밑작업이며 새 전투는 아직 없다.

## dayoff53 확인 순서

1. [격리 목록](../../Legacy/Carve/2026-09-30/inventory.md)에서 폐기 범위와 보존 도구를 확인한다.
2. 저장소 루트에서 `& ./Tools/Verify-CarveQuarantine.ps1`을 실행하여 현재 파일과 원본 보존 상태를 확인한다.
3. Unity 6000.5.10f1에서 프로젝트를 열고 Console의 컴파일 상태를 확인한다. 기존 카브 씬은 실행 성공을 기대하는 검증 씬이 아니다.
4. 필요하면 DDBattleInGame.prefab의 시각 요소가 보존되어 있고 구형 스크립트가 Missing으로 표시되는지 살핀다. Missing Script 제거/저장은 하지 않는다.
5. 새 전투 구현 시 별도 씬에서 시작→예약→실행→승패를 검증한다. 기존 에셋은 필요한 시각 요소를 재사용하고 새 코드로 명시적으로 연결한다.

## 다음 구현과 남은 사항

M1은 `MaseiKivotos` 네임스페이스의 규칙 로직과 Unity 연결부를 새 어셈블리로 나누는 방향으로 진행한다. 기존 전투 프리팹 전체를 그대로 연결하기보다 필요한 외형·애니메이션·UI 리소스를 선별하여 새 검증 씬을 구성한다. 카브 데이터의 수치나 enum을 마키보 규칙으로 자동 간주하지 않는다.

Q-001~Q-006 및 C-001~C-009의 미정 규칙은 그대로 유지한다. 새 전투의 테스트와 리소스 데이터 이행은 후속 작업이다. 보관 코드 복구는 새 구현의 일반적인 의존성 해결 수단으로 사용하지 않는다.

Odin/Sirenix 에디터 초기화 예외의 호환성 확인은 별도 기술 과제로 남긴다. 이번에는 플러그인 교체나 리소스 제거로 범위를 넓히지 않았다.
